## Why this handoff exists

Two days of "fix → test green → relaunch → bug still there" loop. Today's session shipped real B-01 substrate fixes (tool catalog enumeration + dispatch routing) but live testing kept surfacing more wired-but-dead failures: voice input dead, TTS silent, camera button dead, chat history not threaded, model name paraphrased, chat scroll broken. The user called the loop and proposed a fundamental architectural change instead of more tactical patches:

> "The front-end UI needs to be completely divorced from the backend. There needs to be a clear API that operates and shows how each part of the entire system works. That is completely testable as an end-to-end test, independent of the particular UI stuff."

**Decision locked:** stop fixing individual bugs. Design a backend API that represents 100% of Jarvis's behavior, frontend-agnostic, programmatically testable. Existing carry-forward bugs (B-02..B-07) get fixed *against* the new API once it's locked. This handoff is the boundary between the bug-fix loop and the design pivot.
