# Jarvis Roadmap — 2026-05-12

**Supersedes** `.planning/ROADMAP.md` (2026-04-22), which describes the original 9-phase GSD build sequence. That sequence shipped — v0.12.0 is in tree. This document re-frames remaining work around **user-facing capability** rather than build phase.

## What we're building

A personal, always-on macOS AI assistant styled after the Iron Man "Jarvis" HUD. Native Swift/SwiftUI host with an embedded React + R3F web layer, an in-process agent loop talking to Claude Opus 4.7 (Ollama as first-class alternate), MCP tools for OS integration, and a fully-local voice pipeline (openWakeWord → SpeechAnalyzer → AVSpeechSynthesizer/Orpheus). Single user, single machine, no commercial shipping concerns.

The core value the user is buying is **ambient presence**: "it's always there, I can talk to it, it gets things done on my Mac." Voice that actually fires. Listening that produces transcripts. Seeing through the camera. Facts that persist and get recalled. Debugging dialogs that show real state. UI that doesn't have basic correctness bugs.

The architecture is settled and is not relitigated here. The story this roadmap tells is sequencing: **a working system first, a typed API second, polish third.**

## Where we are today

142 open issues. Five fresh audits (2026-05-12) covering Memory, MCP/Agent, Voice, Vision, and Bus/HUD — collectively producing ~36 findings ranging from `severity:critical` (system-breaking) to `severity:low` (cosmetic drift). Today's work landed the schema fix that unblocks memory writes, brought the Dev Overlay from wired-but-dead to fully populated, and surfaced a comprehensive picture of what is broken right now. The Round 4 strict-mode milestone is on tree; v0.12.0 audit-and-stabilize is the active workstream.

The Jarvis API Migration Plan (`.planning/architecture/JARVIS-API-MIGRATION-PLAN.md`) is locked: 8 sequenced phases (M-0 → M-7) that move the entire client-facing surface from ad-hoc `BusInbound`/`BusOutbound` cases to typed `JarvisAPI` surfaces (`Self`, `Settings`, `Diagnostics`, `Memory`, `Vision`, `Voice`, `Turn`). That migration dissolves the carry-forward bugs B-02 through B-08 as a natural consequence — but it is 4–5.5 calendar weeks of work, and the user does not have a working system to use while it is in flight.

This roadmap therefore splits work into two lanes: **v0.1/v0.2 = tactical fixes so today's Jarvis works end-to-end**, and **v0.5/v0.8 = the typed-API migration**. Some CRITICAL audit findings will be re-fixed during the migration; v0.1 applies the tactical patch anyway, because the user needs Jarvis working *now*.

- **v1.1 depends on v0.8** for the carry-forward bugs to be closed first.

## How to read this roadmap

Each milestone is **a coherent user outcome**, not a date. The issues in each milestone are sequenced for atomic-commit work; within v0.1, most fixes are independent (Voice CRITs cluster, Memory CRITs cluster, UX is its own lane). Within v0.5/v0.8 the migration plan is the authoritative sequence: M-0 blocks M-1 blocks M-2 etc., strict topo-sort.

Carry-forward bugs B-02 through B-08 close as follows:

## What this roadmap deliberately does NOT include

- **Multi-tenant / auth / commercial shipping** — out of scope per `PROJECT.md`. Single-user personal project.
- **Screen capture / ScreenCaptureKit** — deferred to v2.
- **Multi-panel holographic HUD / ambient data tiles** — v2.
- **Broader MCP tool catalog beyond the starter three** — additive once the loop works; v2.
- **Cloud TTS/STT** — hard rule.
- **Sonnet as primary model** — superseded by Opus 4.7.
- **Multi-machine sync (iCloud / backend)** — local-first until single-machine proves out.
- **Fixing all 22 HIGH + 22 MEDIUM AUDIT-R4 findings as a discrete gate** — absorbed into build phases per `PROJECT.md`.
