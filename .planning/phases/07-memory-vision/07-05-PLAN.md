<objective>
Build the **frame-attach + multimodal LLMProvider + T1/T2/T3 vision routing**
surface for VISION-04. This plan extends the cross-provider contract to carry
images, adds image-aware request-body encoding to both production providers,
introduces the `Vision`-package-owned `VisionRouter` that implements the D-16
tier ladder with D-17 automatic T1→T2 escalation and D-18 explicit-only T3
escalation, and lands the `FrameAttachController` whose discardFrame call
site on the assistant-turn-complete edge is the only place captured image
bytes leave memory. Concretely:

- **D-18 protocol extension.** `LLMProvider` gains a single new method:

  ```swift
  func stream(
      messages: [LLMMessage],
      images: [ImageBlock],
      tools: [ToolSchema],
      toolChoice: ToolChoice,
      model: ModelID,
      maxOutputTokens: Int,
      cacheHints: CacheHints?
  ) -> AsyncThrowingStream<LLMEvent, Error>
  ```

  A default protocol extension forwards to the existing single-modal
  `stream(messages:tools:toolChoice:model:maxOutputTokens:cacheHints:)`
  whenever `images.isEmpty`, so non-vision providers (and the
  `MockLLMProvider` in tests) keep compiling unchanged. `AnthropicProvider`
  and `OllamaProvider` override the default with image-aware request-body
  encoding.

- **TurnInput multimodal.** `TurnInput` gains `images: [ImageBlock]`
  (default `[]`) plus a `TurnInput.withImages(_:_:)` factory. Existing
  call sites compile unchanged because the field is defaulted.

- **Anthropic image_block encoding (D-18 / T3 path).** Per the Anthropic
  Vision API, each image is serialized inline alongside the user message's
  text content blocks as:

  ```json
  {
    "type": "image",
    "source": {
      "type": "base64",
      "media_type": "image/jpeg",
      "data": "<base64-encoded-jpeg-bytes>"
    }
  }
  ```

  `RequestBody.buildMultimodalUserContent(text:images:)` is the SOLE
  producer of this block in the entire codebase.

- **OpenAI-compat image_url encoding (T1 + T2 paths).** Both `gemma4:31b`
  via Ollama and `Qwen3.5-35B-A3B-VL` via vllm-mlx speak the OpenAI vision
  request shape:

  ```json
  {
    "type": "image_url",
    "image_url": { "url": "data:image/jpeg;base64,<base64>" }
  }
  ```

  `OllamaProvider` gets the encoding; `VllmMlxProvider` is `OllamaProvider`
  configured with `useOpenAICompat: true` against the vllm-mlx port.

- **VisionRouter (D-16 tier ladder).** The router exposes
  `route(for: ImageBlock, prompt: String, explicitCloudOptIn: Bool)`
  returning `(provider: LLMProvider, model: ModelID, tier: VisionTier)`.
  Default tier is **T1** (`gemma4:31b` via Ollama). After T1 streams its
  response, `VisionRouter.evaluatePostResponse(_:config:)` checks the
  D-17 heuristic; if it fires, it silently re-runs on **T2** (vllm-mlx
  Qwen3.5-35B-A3B-VL). Only when `explicitCloudOptIn` is true does the
  router reach **T3** (`claude-opus-4-7` via `AnthropicProvider`).

- **D-17 automatic T1→T2 escalation heuristic.** Implemented as a pure
  function `VisionEscalationHeuristic.evaluateLowConfidence(_:config:)`
  reading from a planner-tuned `VisionRouterConfig` struct committed to
  source. Substring set: `{"i'm not sure", "i am not sure", "unclear",
  "cannot determine", "can't determine", "i don't know", "hard to tell"}`.
  Length threshold default: 24 chars. **The set and threshold are NAMED
  fields on a public struct, not magic constants buried in the router
  function body** — they are reviewable and tunable in version control.

- **D-18 explicit-only T3 escalation.** `EscalationPhraseDetector`
  `matchesCloudOptIn(_:)` is the ONLY function whose return value can
  flip the router to T3. Phrase set: `{"send to opus", "use cloud",
  "use opus", "send to claude"}`. `ContextBuilder` is the only outside-
  of-tests caller. `VisionRouterCloudOptInGrepTests` enforces structurally
  that no other code path in `packages/Vision/Sources/Vision` references
  `AnthropicProvider` or `claude-opus` outside files that also reach
  `matchesCloudOptIn` — the **no-auto-cloud invariant** of D-18.

- **vllm-mlx sidecar via ChildSpawnGate.** `VllmMlxSidecar.start()` calls
  `try await ChildSpawnGate.shared.prepare()` BEFORE `Process.run()` and
  sets `proc.environment = ChildSpawnGate.minimalEnvironment` (verbatim:
  `["PATH": "/usr/bin:/bin"]`). It never inherits parent process env or
  FDs. This mirrors the Phase 5 MCP helper spawn pattern. Lifecycle is
  **lazy**: not started at install time; first T2 need triggers
  `ensureRunning()` with a bounded 60-second `/health` warmup window.

- **`@available(macOS 26)` + feature flag fallback.** `VllmMlxAvailability`
  combines a runtime version guard, configured-binary-path existence
  check, and the `features.vision.tier2` feature flag. When unavailable,
  T2 escalation is silently dropped — but the router NEVER falls through
  to T3 without an explicit user opt-in phrase. The user's frame stays
  on T1.

- **FrameAttachController (D-13 / D-14 / D-15).** Single actor with three
