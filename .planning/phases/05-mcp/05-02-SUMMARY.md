# Phase 5 Plan 2: helpers-time-clipboard Summary

Built and shipped `mcp-time` and `mcp-clipboard` as separately-codesigned nested `.app` bundles under `Jarvis.app/Contents/Helpers/`, exposing `get_time` (ISO 8601 current time) and `get_clipboard` (system pasteboard read with mandatory `NSPasteboardTypeFileURL` refusal). Closes MCP-02 and MCP-03 with end-to-end Xcode build, codesign chain, and JarvisMCP-package round-trip integration tests both passing.

## What landed

**Two SPM helper packages** under `mcp-servers/` (peer of `packages/`):
- `mcp-servers/mcp-time/` — single executable target with one `get_time` MCP tool that returns `ISO8601DateFormatter().string(from: Date())` with fractional seconds.
- `mcp-servers/mcp-clipboard/` — executable target plus a testable `PasteboardReader` library + `PasteboardLike` protocol. The MCP `get_clipboard` tool reads `NSPasteboard.general` through a `SystemPasteboard` adapter, returns refusal when types contain `.fileURL` regardless of accompanying string content, returns "(clipboard empty)" when nothing usable, returns the string otherwise.

**Helper bundle layout** in the built `Jarvis.app`:
```
Jarvis.app/Contents/Helpers/
├── mcp-time.app/
│   └── Contents/
│       ├── Info.plist                      (LSUIElement=YES, LSBackgroundOnly=YES, com.koftwentytwo.jarvis.mcp-time)
│       ├── MacOS/mcp-time                  (statically-linked Release; Debug uses the incremental .debug.dylib)
│       ├── Resources/mcp-time.entitlements (empty <dict/>; codesign.sh consumes from this path)
│       └── _CodeSignature/                 (per-helper signature, never re-signed by --deep)
└── mcp-clipboard.app/                      (mirrored layout, com.koftwentytwo.jarvis.mcp-clipboard)
```

**Build wiring** (`project.yml`):
1. Top-level `swift-sdk` package registered (exact 0.12.0, same as `packages/MCP/Package.swift`).
2. Two new application targets (`mcp-time`, `mcp-clipboard`) each:
   - Link to swift-sdk's `MCP` product.
   - Carry per-config codesign settings (Debug ad-hoc, Release hardened-runtime + `--options=runtime --timestamp`).
   - Run a postBuildScript that copies `Support/<helper>.entitlements` into the built bundle's `Contents/Resources/<helper>.entitlements` so `scripts/codesign.sh` finds them.
3. The `Jarvis` target gains `target: mcp-time` + `target: mcp-clipboard` dependencies (`embed: false, link: false` — helpers are independent .app subprocesses, not linked frameworks).
4. A new `Copy MCP helpers into Contents/Helpers/` postBuildScript on the Jarvis target shells `cp -R "${BUILT_PRODUCTS_DIR}/<helper>.app" → "${TARGET_BUILD_DIR}/Jarvis.app/Contents/Helpers/<helper>.app/"` for both helpers, runs BEFORE `Codesign bundle (deepest-first)`.

**Integration tests** (`packages/MCP/Tests/MCPTests/`):
- `HelperBundleLocator.swift` — shared resolver: `JARVIS_MCP_<NAME>_PATH` env override → `Bundle.main` walk → DerivedData walk (Release-preferred, skips Debug helpers with `.debug.dylib`) → `XCTSkip`.
- `MCPTimeIntegrationTests.test_get_time_returns_iso8601` — registers helper, calls `get_time`, parses through `ISO8601DateFormatter`, asserts ±60s of `Date()`.
- `MCPClipboardIntegrationTests.test_get_clipboard_runs_and_returns_one_content_item` — registers helper, calls `get_clipboard`, accepts any of (text / empty / fileURL refusal) — refusal logic itself is exhaustively unit-tested at PasteboardReader level.

## Per-helper TCC posture

Both helpers ship with **empty entitlements** (`<dict/>`). Hardened Runtime is inherited from codesign flags. Neither carries `automation.apple-events` — that belongs only to `mcp-applescript` (Plan 05-03). `scripts/verify-entitlements.sh --post-codesign`'s per-helper grep confirms this gate stays green.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Renamed `main.swift` → `MCPTimeMain.swift` / `MCPClipboardMain.swift`**
- **Found during:** Task 1 (mcp-time built fine via `swift build`, broke under `xcodebuild`); Task 2 (mcp-clipboard broke immediately).
- **Issue:** Xcode rejects `@main` on a struct in a file named `main.swift` ("`@main` attribute cannot be used in a module that contains top-level code"). Standalone `swift build` tolerated it; `xcodebuild` did not.
- **Fix:** Renamed both files. `@main` now works because the file is no longer auto-treated as script-mode top-level code.
- **Files modified:** `mcp-servers/mcp-{time,clipboard}/Sources/mcp-{time,clipboard}/MCP{Time,Clipboard}Main.swift`.
- **Commits:** `06bae38`, `69e5021`, `c9a58b4`.

**2. [Rule 1 — Bug] `SystemPasteboard` made `@unchecked Sendable`**
- **Found during:** Task 2 GREEN.
- **Issue:** `NSPasteboard` is not declared `Sendable` in AppKit; the original `SystemPasteboard` struct held an `NSPasteboard` field, and its `PasteboardLike` conformance (which extends `Sendable`) tripped the SWIFT_STRICT_CONCURRENCY=complete checker.
- **Fix:** Removed the stored `NSPasteboard` reference; `SystemPasteboard` is now `@unchecked Sendable` and reads via the `NSPasteboard.general` singleton inside each method.
- **Files modified:** `mcp-servers/mcp-clipboard/Sources/mcp-clipboard/MCPClipboardMain.swift`.
- **Commit:** `69e5021`.

**3. [Rule 3 — Blocking] xcodegen `copyFiles` doesn't resolve target products from BUILT_PRODUCTS_DIR**
- **Found during:** Task 3 (first Debug build produced empty `Jarvis.app/Contents/Helpers/`).
- **Issue:** The plan called for `copyFiles: { destination: wrapper, subpath: Contents/Helpers, files: [mcp-time.app, mcp-clipboard.app] }`, but xcodegen treats `files:` paths as SRCROOT-relative; nothing resolves to the BUILT_PRODUCTS_DIR helper apps, so the phase ran empty.
- **Fix:** Replaced `copyFiles` with a postBuildScript on the Jarvis target that `cp -R "${BUILT_PRODUCTS_DIR}/<helper>.app" → "${TARGET_BUILD_DIR}/${WRAPPER_NAME}/Contents/Helpers/<helper>.app"` for both helpers. Matches the plan's deviation_rules allowance ("If xcodegen doesn't directly support nested .app bundles via Contents/Helpers/<Name>.app/, generate the helper bundles via separate xcodebuild targets and copy them in via a Build Phase script."). Code Sign On Copy stays disabled — `scripts/codesign.sh`'s deepest-first walker remains the authoritative signer.
- **Files modified:** `project.yml` (the Jarvis `copyFiles` block became a postBuildScript).
- **Commit:** `c9a58b4`.

**4. [Rule 1 — Bug] Integration tests use synchronous `await client.shutdown()`**
- **Found during:** Task 3 verification (full JarvisMCP suite run).
- **Issue:** Initial integration tests used `defer { Task { await client.shutdown() } }` — fire-and-forget. The test returned before shutdown completed, helper stdio FDs leaked into the next test, and `MCPRestartTests/test_100_crashCycles_noFDLeak` crashed on a `ChildSpawnGate.swift:47` `fatalError` ("FD 3 is not FD_CLOEXEC; origin must be instrumented to set O_CLOEXEC at open time").
- **Fix:** Both integration tests now `await client.shutdown()` synchronously at end-of-test, matching `MCPClientHappyPathTests`'s pattern.
- **Files modified:** `MCPTimeIntegrationTests.swift`, `MCPClipboardIntegrationTests.swift`.
- **Commit:** `c9a58b4`.

**5. [Rule 1 — Bug] HelperBundleLocator prefers Release over Debug + skips `.debug.dylib`-laden Debug helpers**
- **Found during:** Task 3 verification (`swift test --package-path packages/MCP` hung when DerivedData held only a Debug build).
- **Issue:** Xcode 26 Debug builds emit a `<helper>.debug.dylib` incremental-link artifact whose code signature diverges from the parent's ad-hoc signing; dyld rejects the helper subprocess at load with "different Team IDs", and the JSON-RPC initialize handshake never completes (test hangs indefinitely).
- **Fix:** `HelperBundleLocator` walks DerivedData in `["Release", "Debug"]` order (was `["Debug", "Release"]`); if a candidate has an adjacent `<helper>.debug.dylib`, skip and try the next config. Falls through to `XCTSkip` if neither resolves.
- **Files modified:** `packages/MCP/Tests/MCPTests/HelperBundleLocator.swift`.
- **Commit:** `c9a58b4`.
