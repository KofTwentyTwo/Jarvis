# v0.12.0 Milestone Audit

> **Headline:** All 9 phases passed unit-level GSD verification (5 cleanly, 4 with deferred-but-acceptable gaps, 1 phase 7 with documented cross-phase wiring deferrals that Phase 9 then *did* close at the unit level). However, **three previously-undetected cross-phase blockers + one known stub** mean the v0.12.0 demo has **zero working end-to-end interaction modalities** for the user.

## TL;DR — Milestone Status: `gaps_found`

| Layer | Status |

| Outstanding UAT items | ⚠ 1 (= F-A1-01 / static rings) |

The unit suites correctly verified the *capabilities*. They did not verify that the capabilities *connect into a working app*. The four blockers are all of the form "producer wired ✓, consumer wired ✓, **the cable between them is missing**." Boundary grep gates by design enforce that classes don't *cross* layers — they don't catch *absence of wiring*.

## Cross-Phase Findings

### 🔴 BLOCKERS (4)

#### BLOCKER-INT-1 — `NoopBusGateway` swallows tool-call events
**Affected:** HUD-07, MCP-01..04, TOOL-01..03 (visible tool execution loop).
**Root cause:** `App/AppDelegate.swift:467` constructs `NoopBusGateway()` with comment `CR-02: orchestrator wiring (later plan) replaces`. The replacement plan never landed. Producer (`ConfirmingToolDispatcher` lines 132/167/175/185/200/209) emits correctly. Consumer is a function with `{}`. HUD `ToolCallCard` consumer is fully wired in TS but never receives a card.

#### BLOCKER-INT-2 — `tokenDelta` / `turnStarted` / `turnEnded` never emitted to webview
**Affected:** TEXT-01, TEXT-02, AGENT-04, AGENT-10, HUD-04..06.
**Root cause:** `OutboundBatcher.postToken(...)` exists but cross-tree grep shows zero call sites. The orchestrator's `events` AsyncStream has 5 subscribers (memory/transcript/devOverlay/frameAttach/voice) — no `.bus` subscriber. Webview chat panel renders forever-empty `chatEvents` array.

#### BLOCKER-INT-3 — HUD has no chat input UI
**Affected:** TEXT-01, HUD-07, brief week-one #7.
**Root cause:** `webview/packages/hud/src/chat/ChatPanel.tsx` is read-only. Cross-tree grep across webview HUD shows zero producer of any inbound bus message (`chatSubmit`, `frameAttachRequested`, etc.). Swift inbound side IS wired (`AppDelegate.swift:1404-1407` → `handleChatSubmit` → `orchestrator.submit`), but nothing on the JS side fires that producer.

#### BLOCKER-INT-4 — `CameraCapture` 1×1 black JPEG (= C1)
**Affected:** VISION-01..05, MEM-08, TEXT-03 (any vision turn).
**Root cause:** `packages/Vision/Sources/Vision/CameraCapture.swift:106-115` returns `Self.onePixelJPEG()` with comment "Replaced by AVCapturePhotoOutput delegate flow in 07-05". Phase 07-05 closed without that replacement. The dispatch pipeline is correct; the data flowing through it is junk.

### 🟡 WARNINGS (2)

#### WARN-INT-1 — TTS engine `nil`; voice loop is mute
**Affected:** VOICE-11, end-to-end voice UX. Voice in works; voice out is silent.

#### WARN-INT-2 — `sessionHistory` outbound declared but never emitted
**Affected:** chat panel hydration on app launch. Even with BLOCKER-INT-3 fixed, conversation history from prior sessions wouldn't appear.

### 🟢 COSMETIC (2)
- **F-A2-01:** `WebviewBridgeOutboundTests.swift:80` asserts retired `JarvisBusWorld` (cosmetic for now; medium during Phase E TDD).
- **stale-comment-1:** `AppDelegate.swift:1190-1192` claims "deferred" though Phase 9 wired it.
