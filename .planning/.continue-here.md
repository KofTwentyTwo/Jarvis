Phase B's `/gsd-audit-milestone` confirmed v0.12.0 has 4 cross-phase BLOCKERS that 9/9 unit-level GSD verifications missed. The pattern: producers wired ✓, consumers wired ✓, **the cable between them is missing**. Boundary grep gates by design enforce that classes don't *cross* layers — they don't catch *absence of wiring*. Phase F1 (top-level integration tests) is the structural fix; we landed test #1 of 4 this session.
- [ ] **CONSTRAINT: WKContentWorld isolates `window.*` property access.** Original closure was at fb41c5f; first integration test (`packages/Bus/Tests/BusTests/RealWKWebViewIntegrationTests.swift`, commit 326a27d) catches future regressions. The auto-ack-hello at the stub layer means handshake works without a bundle handler. Any future bus/webview work MUST be tested against a real WKWebView, not just the JSEvaluator seam.
- [ ] **CONSTRAINT: Compiler weak-ref warnings are LOAD-BEARING, not noise.** "Weak reference will always be nil" warnings on `NSMenuItem.target = ClosureTarget(...)` were the actual bug. Fixed at commit `8fbe2d6` via `objc_setAssociatedObject`. Do not silence Swift weak-ref / Sendable warnings without proving the underlying invariant holds another way.
- [ ] **CONSTRAINT: "Replaced in 0X-0Y" comment-stubs ROT.** `CameraCapture.captureFrame()` still returns 1×1 black JPEG ("Replaced by AVCapturePhotoOutput delegate flow in 07-05" — Phase 7 closed without the replacement). `NoopBusGateway` still no-ops tool-call events ("CR-02: orchestrator wiring (later plan) replaces" — never did). Phase F2 (`scripts/check-no-leftover-stubs.sh` linter) is the targeted fix; until it lands, every "Replaced in X-Y" comment is a manual-tracking liability.

Don't trust the traceability table as authoritative; consult phase SUMMARY frontmatters' `requirements_completed` arrays instead. Phase G's milestone-close should reconcile these in one sweep.

## Critical Anti-Patterns (carry-forward from prior arc)

| Pattern | Description | Severity | Prevention Mechanism |
|---|---|---|---|
| Cross-world handoff via shared globals | Stub in `WKContentWorld(name:"X")`, page bundle in `.page` world, both touch `window.jarvisBus` thinking they share — they don't. | blocking | All bridge-worlds aligned to `.page`. New code MUST use the explicit `contentWorld` constructor parameter on `WebviewBridge`. **Now caught by `RealWKWebViewIntegrationTests` (326a27d)** as a regression-protection test. |
| Test seam that bypasses the bug class | `JSEvaluator` protocol let Bus tests run without a real WKWebView, so WKContentWorld behavior was never exercised. | blocking | F1's `RealWKWebViewIntegrationTests` (326a27d) closes this for the handshake. Three more F1 tests still TODO (chat-turn, wizard happy path, hotkey toggle). |
| `NSMenuItem.target = T()` weakly held | NSMenuItem.target is `weak`; assigning a fresh trampoline lets it deallocate immediately. | blocking | `MenuBarContextMenu.makeItem(...)` keeps the trampoline alive via `objc_setAssociatedObject`. Pattern documented in commit `8fbe2d6`. Must be applied to any future closure-driven NSMenuItem / NSToolbarItem. |
| Future-tense stub comments | `// Stub: replaced in 0X-0Y` where 0X-0Y closed and the stub stayed. | blocking | Phase F2 — `scripts/check-no-leftover-stubs.sh` build-time linter. NOT YET WRITTEN. Two known instances: CameraCapture.swift:106, AppDelegate NoopBusGateway. |
| Single-slot pre-handler buffer | `_pendingHello` was a single slot; burst messages clobbered each other. | advisory | Use a FIFO queue for any pre-handler buffering. Pattern fixed in `Injection.js` commit `e8a956c`. |
| Producer wired ✓, consumer wired ✓, cable missing ✗ | The Phase B audit failure mode. Tools/tokens/tool-call events never reach the webview because no `.bus` subscriber drains the orchestrator broadcaster (now half-fixed; see commit 602a95b for the tokenDelta wire). | **NEW** blocking | Phase F1 integration tests. Phase F3 — extend gsd-verifier to require an end-to-end smoke for any phase that adds a producer/consumer pair. |

The Bus package's existing SPM test target already imports WebKit and uses real WKWebView. OutboundBatcher coalesces tokens at ~30 Hz internally, so tail-dropping deltas under extreme overload is preferable to back-pressuring the orchestrator.
